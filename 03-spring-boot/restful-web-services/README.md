# RESTful Web Services

> Designing a REST API with Spring Boot, one topic at a time: endpoints and JSON, request data, CRUD with the right status codes, validation and errors, filtering, versioning, docs, tests and security. Based on the in28minutes Spring Boot course. The course's own code is in [`reference/`](../../reference/in28minutes-spring-microservices-v3/02.restful-web-services), so you can compare.

**Before this:** [spring-boot-basics](../spring-boot-basics/).

## Run it
No database. The users are kept in an in-memory store that is safe to use from many threads at once.
```bash
./mvnw spring-boot:run          # Windows: mvnw.cmd spring-boot:run
./mvnw test
```
It runs on port 8080. Swagger UI (a web page to try the API) is at http://localhost:8080/swagger-ui.html. Click **Authorize** and log in as `admin` / `admin123`.

**Logins (topic09):** reading is open to everyone. Changing data needs `admin` / `admin123`. `reader` / `reader123` is logged in, but not allowed to change anything. Set `ADMIN_PASSWORD` / `READER_PASSWORD` for anything that is not a local demo.

```bash
curl localhost:8080/users
curl -i localhost:8080/users/99                                               # 404 ProblemDetail
curl -i -u admin:admin123 -X POST localhost:8080/users -H "Content-Type: application/json" \
     -d '{"name":"Asha","birthDate":"2000-01-01"}'                             # 201 + Location
curl -i -u admin:admin123 -X DELETE localhost:8080/users/3                    # 204
curl -H "X-API-Version: 2" localhost:8080/person                              # version 2
```

## Topic notes

### 01-02 Endpoints and request data
- **How:** a `@RestController` method returns data. A `String` goes out as text. An object or record is turned into JSON by Jackson.
- **Where request data lives:**
  - the **path** says *which* resource (`@PathVariable`);
  - the **query string** carries options (`@RequestParam`, with `defaultValue`);
  - **headers** carry extra information about the request (`@RequestHeader`);
  - the **body** carries the data for POST/PUT (`@RequestBody`).

### 03 CRUD resource
- **Why:** clients depend on status codes, so they must be correct.
- **How:**
  - POST returns **201** with a `Location` header (the URL of the new user). It is built from the current request, so the host is never hard-coded.
  - DELETE returns **204**.
  - A missing id is **404**: the controller throws `UserNotFoundException`, and topic04 turns it into the response.
- **Mistake (fixed):** the store used to be a static `ArrayList` with a static counter. Requests run on many threads at the same time, so two users could get the same id. Like two railway counters selling the same seat. It now uses `ConcurrentHashMap` and `AtomicInteger`.

### 04 Validation and errors
- **How:**
  - `@Valid @RequestBody User` checks `@Size`, `@Past` and `@NotNull` before the method runs.
  - One `@RestControllerAdvice` (extending `ResponseEntityExceptionHandler`) returns every error in the same **ProblemDetail** JSON shape (RFC 9457). This includes Spring's own errors, such as bad JSON.
- **Exercise:** add `@Email` to a new field and test it.

### 05 Filtering and DTOs
- **How:**
  - `@JsonIgnore` never sends a field. That is right for secrets.
  - `@JsonView` sends a different set of fields for each endpoint.
  - A **DTO** (Data Transfer Object) record is a separate type just for the response. It is the clearest choice for real APIs.
- **Jackson 3 note:** Boot 4 moved Jackson's code to `tools.jackson.*`, but the annotations stayed in `com.fasterxml.jackson.annotation`.

### 06 Versioning
- **Why:** changing a JSON shape breaks the clients that already use it. A new version lets both old and new clients work.
- **How:**
  - Spring Framework 7 has versioning built in. `configureApiVersioning` says where the version is sent (a header here), and `@GetMapping(version = "2")` chooses the handler.
  - With no header, you get the default version. An unknown version returns a 400.
  - `/v1/...` URI versioning is shown next to it, for comparison. Pick one style for each API.

### 07 OpenAPI
- **How:** springdoc generates `/v3/api-docs` and Swagger UI from the code, so the docs can never fall out of step with the code. `OpenApiConfig` adds the title and the HTTP Basic "Authorize" button.

### 08 Testing
- **How:**
  - `@WebMvcTest(UserResource.class)` loads only the web layer, so it is fast. You `@Import` anything else it needs. MockMvc and `jsonPath` check the status and the JSON.
  - `@SpringBootTest` starts the whole app. One or two of those are enough.
- **Gotchas:**
  - The tests share one context (the running set of beans), so they shared the in-memory store too, until `@DirtiesContext` gave each test a fresh one. Tests must never depend on the order they run in.
  - In Boot 4, security in `@WebMvcTest` needs `spring-boot-starter-security-test`.

### 09 Security
- **How:**
  - Adding the security starter locks **everything**. `SecurityConfig` then opens GET requests and the docs, and asks for the `ADMIN` role for changes.
  - A missing or wrong login gives **401** (who are you?). Logged in but not allowed gives **403** (you can't do this).
  - Passwords are stored hashed (`{bcrypt}`).
  - CSRF protection is off only because this is a stateless API, and the client sends the login with every request. A browser app that uses session cookies must keep CSRF protection on.
